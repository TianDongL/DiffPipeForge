# MiniMax H3 训练参数与 24GB 显存指南

本文说明如何在 DiffPipeForge WebUI 中配置 MiniMax H3 LoRA，并用 3 个训练步先验证模型、数据集、缓存、反向传播、保存和检查点恢复链路。云平台的部署、挂载路径和停机规则分别见：

- [优云智算部署与训练](../cloud/youyun_zh.md)
- [晨羽智云部署与训练](../cloud/chenyu_zh.md)

> 3 步训练只用于烟雾测试。它能证明整条训练链已经跑通，不能用于判断 LoRA 最终质量，也不能要求 loss 在 3 步内持续下降。

## 1. 当前支持范围

MiniMax H3 当前支持：

- 文生图训练；
- 文生视频训练；
- 带音轨视频的联合训练，视频中的音频会自动参与训练；
- 无音轨视频；
- 图片和视频混合数据集；
- 在 ComfyUI 格式 int8 convrot 基座上训练 LoRA 等适配器。

当前不支持参考图、编辑、图生视频、首帧条件或首尾帧条件训练。只使用图片训练虽然可以工作，但长时间训练可能削弱模型原有的视频与运动理解能力。

量化基座只用于适配器训练。若把“适配器类型”设为 `None` 进行全量微调，必须改用非量化模型，并重新评估显存需求。

## 2. 先准备数据集

### 2.1 视频与标注必须同名

每个视频旁边放一个同名 `.txt` 文件，只有扩展名不同。本文的 3 步验收使用下面 3 对文件：

```text
my_dataset/
├── 2.mp4
├── 2.txt
├── 3.mp4
├── 3.txt
├── 4.mp4
└── 4.txt
```

`2.txt` 中写对 `2.mp4` 的自然语言描述，建议保存为 UTF-8。若文件名不一致，例如 `2.mp4` 配 `caption_2.txt`，训练器不会把它们自动配对。

浏览器版不需要先把文件传到 JupyterLab：

1. 在“数据集设置”点击“选择视频和标注”；
2. 一次选择 `2/3/4.mp4` 和对应的 `2/3/4.txt`；
3. 确认界面显示 3 个视频、3 个标注且没有配对错误；
4. 点击“上传并使用此数据集”；
5. 上传完成后让 WebUI 自动填写“输入路径”，不要再手动覆盖。

没有独立可写盘时，自动路径形如 `/workspace/DiffPipeForge/web_uploads/dataset-...`；若存在真实可写 `/cloud`，则形如 `/cloud/DiffPipeForge/uploads/dataset-...`。实际值以页面显示为准。不要填写本机 `C:\...` 路径、浏览器下载目录或单个视频文件。

“无打标文件处理”建议保持“跳过无打标图片（默认）”。这样缺失 `.txt` 的素材会被排除，不会在用户不知情的情况下以空提示词训练。

### 2.2 3 步烟测使用 3 个短视频

第一次训练建议只放 3 个可正常播放的短视频及其 3 个同名 `.txt`：

- 容易在 1 个 epoch 内形成 3 个训练步；
- 缓存时间较短；
- 遇到坏视频或错标注时容易定位；
- 通过后再切换完整数据集，不要直接拿烟测结果判断成片质量。

MiniMax H3 会把视频统一按 24 fps 预处理，把音频重采样到 32 kHz。源视频无音轨也可以训练。

## 3. 为什么烟测使用 34 帧而不是 33 帧

MiniMax H3 的视频 VAE 按每 17 帧一组编码。训练器会把目标帧数向下对齐到 17 的倍数，单张图片则作为 1 帧的特殊情况处理。

因此：

- `34 = 17 × 2`，是有效的两组视频帧；
- `33` 会向下对齐，不能得到期望的 34 帧片段；
- 更长视频可使用 `68`、`102`、`136` 等 17 的倍数；
- 3 步烟测固定填 `[34]`，便于控制缓存时间和显存占用。

界面中的通用占位示例可能显示 `[1, 33, 65]`，那不是 MiniMax H3 的推荐值。配置 MiniMax H3 时请主动改成 `[34]`。

## 4. 3 步烟测参数总表

下面是 24GB 显卡已经采用过的最小烟测组合。没有列出的高级字段先保留界面默认值，不要一次修改太多变量。

### 4.1 数据集设置

| WebUI 字段 | 烟测值 | 说明 |
| --- | --- | --- |
| 输入路径 | 服务器上的数据集目录 | 目录内放视频和同名 `.txt`，不要填本机 Windows 路径 |
| 分辨率 | `[384]` | 先验证链路；正式训练再按显存和数据质量提高 |
| 启用宽高比分桶 | 启用 | 让不同尺寸素材进入合适的桶 |
| 自定义宽高比分桶 | `[[16, 9]]` | 3 个烟测视频应使用或接近 16:9 |
| 最小宽高比 | `0.5` | 当前界面默认值；有自定义 16:9 桶时不是烟测关键变量 |
| 最大宽高比 | `2.0` | 当前界面默认值 |
| 分桶数量 | `7` | 当前界面默认值 |
| 帧数分桶（视频） | `[34]` | 两组 17 帧，不能照抄通用的 33 帧示例 |
| 重复次数 | `1` | 3 个样本足以完成 3 步链路验证 |
| 验证集 | 禁用 | 首次烟测不做质量评估，减少额外缓存和显存占用 |

保存后应能在当前项目的 `dataset.toml` 中看到对应字段。路径必须是 Linux 服务器路径并使用 `/`。

### 4.2 模型配置

MiniMax H3 四个文件共 `53,924,785,072` 字节。服务器端下载还需要缓存、临时文件和文件系统余量，因此下载目标至少预留 **60 GiB 可用空间**。

#### 已经挂载在 `/model`

在 WebUI 选择 `MiniMax H3` 后点击“识别 MiniMax 四文件”。界面会按精确文件大小和 SHA-256 校验并自动映射四个字段。优云常见的完整路径如下：

| 字段 | 精确路径 | 字节数 |
| --- | --- | ---: |
| Diffusion 模型路径 | `/model/ModelScope/Comfy-Org/MiniMax-H3/diffusion_models/minimax_h3_fl2va_pruned_int8_convrot.safetensors` | `20,970,379,616` |
| 文本编码器路径（Qwen3-VL） | `/model/ModelScope/Comfy-Org/MiniMax-H3/text_encoders/qwen3vl_32b_minimax_h3_int8_convrot.safetensors` | `27,141,342,152` |
| VAE 路径 | `/model/ModelScope/Comfy-Org/MiniMax-H3/vae/minimax_h3_video_vae_fp16.safetensors` | `5,207,808,496` |
| 音频 VAE 路径 | `/model/ModelScope/Comfy-Org/MiniMax-H3/vae/minimax_h3_audio_vae_fp32.safetensors` | `605,254,808` |

`/model` 是公共只读模型盘。识别操作只读取和校验文件，不能把训练输出或缓存写到这里。

#### 由 WebUI 在服务器端下载

点击“一键准备 MiniMax H3”，选择 ModelScope 或 Hugging Face，并使用界面预置的仓库、固定 revision 和四文件清单。下载目标必须可写：有持久盘时使用 `/cloud/DiffPipeForge/models/MiniMax-H3`，否则使用 `/workspace/DiffPipeForge/models/MiniMax-H3`。确认可用空间不少于 60 GiB 后点击“开始服务器下载”。

下载完成后四个路径会自动映射到模型字段。重试时保持同一目标目录以复用未完成缓存，不要在本机下载后再上传，也不要把模型下载进训练输出目录。若文件所在仓库需要令牌，令牌只由服务器环境变量提供，不会写入训练 TOML 或任务日志。

| WebUI 字段 | 烟测值 | 说明 |
| --- | --- | --- |
| 模型架构 | `MiniMax H3` | 必须先选中，之后才会显示 H3 专用字段 |
| Diffusion 模型路径 | 已识别或服务器下载的 int8 convrot 文件 | 必须是上表精确文件 |
| VAE 路径 | `minimax_h3_video_vae_fp16.safetensors` | 视频 VAE，必填 |
| 音频 VAE 路径 | `minimax_h3_audio_vae_fp32.safetensors` | 即使数据集只有图片也必填 |
| 文本编码器路径（Qwen3-VL） | `qwen3vl_32b_minimax_h3_int8_convrot.safetensors` | 必填；int8 文件约 26GB，可在缓存阶段按动态显存策略运行 |
| 基础数据类型（dtype） | `bfloat16` | 训练计算精度 |
| Diffusion 模型数据类型 | `保留检查点原生量化` | 必须保留空覆盖，不要把 int8 基座转换成 bf16/float8 |
| 时间步采样方法 | `uniform` | 当前参考起点 |
| 时间步偏移量（Shift） | `8` | 偏重细节学习的参考起点；最佳值仍需按数据实验 |
| 图片时间步偏移量 | `1` | 图片训练参考起点 |
| CFG 增强训练 | `4` | 已采用的保留蒸馏方式 |
| 训练 / 去蒸馏适配器 | 留空 | 与 `CFG=4` 互斥，不能同时启用 |

选择“保留检查点原生量化”后，保存出的 `trainconfig.toml` 不应出现 `diffusion_model_dtype`。这是正确行为，不是漏写配置。

### 4.3 训练、适配器与优化器

| WebUI 字段 | 烟测值 | 说明 |
| --- | --- | --- |
| 输出文件夹名称 | 唯一名称，例如 `minimax_h3_smoke_01` | 不要和另一训练会话共用输出目录 |
| 批次大小（每 GPU） | `1` | 24GB 显卡安全起点 |
| 梯度累积步数 | `1` | 让 3 步烟测的行为更直观；正式训练可再调整 |
| 管道并行阶段数 | `1` | `CFG > 1` 时强制要求 |
| 激活检查点 | `Unsloth（极致节省显存）` | 24GB 显卡推荐 |
| 交换块数量 | `48` | MiniMax H3 当前允许的最大值；显存最低但速度会下降 |
| 缓存批次大小 | `1` | 降低缓存峰值 |
| 适配器类型 | `LoRA` | 量化基座不能做全量微调 |
| Rank（秩） | `8` | 烟测用较小 rank；正式训练可按目标改成 16/32 等 |
| 适配器数据类型 | `bfloat16` | 与参考配置一致 |
| 优化器类型 | `AdamW Optimi` | bfloat16 训练参考选择 |
| 学习率 | `1e-4` | MiniMax H3 LoRA 参考起点 |
| 最大训练步数 | `3` | 到第 3 步自动停止 |
| 每 N 步保存模型 | `3` | 第 3 步保存 LoRA 权重 |
| 日志打印间隔步数 | `1` | 每一步都能看到 loss |
| 编译模型 | 首次烟测关闭 | 避免把编译等待误认为卡死；正式长训可再启用 |

训练正常结束时还会保存最终训练状态检查点，因此烟测结束后应能看到 `latest` 和对应的 `global_step` 目录。

### 4.4 保存后的关键配置核对

普通用户应通过 WebUI 保存，不需要手写 TOML。若要排查界面是否把值写对，`dataset.toml` 的关键部分应类似：

```toml
resolutions = [384]
enable_ar_bucket = true
min_ar = 0.5
max_ar = 2.0
num_ar_buckets = 7
ar_buckets = [[16, 9]]
frame_buckets = [34]

[[directory]]
path = '/服务器上的/烟测数据集目录'
num_repeats = 1
```

`trainconfig.toml` 的关键部分应类似：

```toml
micro_batch_size_per_gpu = 1
gradient_accumulation_steps = 1
pipeline_stages = 1
activation_checkpointing = 'unsloth'
blocks_to_swap = 48
caching_batch_size = 1
max_steps = 3
save_every_n_steps = 3
steps_per_print = 1

[model]
type = 'minimax_h3'
diffusion_model = '/平台对应路径/minimax_h3_fl2va_pruned_int8_convrot.safetensors'
vae = '/平台对应路径/minimax_h3_video_vae_fp16.safetensors'
audio_vae = '/平台对应路径/minimax_h3_audio_vae_fp32.safetensors'
text_encoders = [{ path = '/平台对应路径/qwen3vl_32b_minimax_h3_int8_convrot.safetensors', type = 'minimax' }]
dtype = 'bfloat16'
timestep_sample_method = 'uniform'
shift = 8
image_shift = 1
cfg = 4

[adapter]
type = 'lora'
rank = 8
dtype = 'bfloat16'

[optimizer]
type = 'adamw_optimi'
lr = 1e-4
```

这套量化烟测配置中不应出现 `diffusion_model_dtype`，也不应出现 `merge_adapters`。前者缺席表示保留 int8 原生量化，后者缺席表示采用 CFG 路线而没有合并训练适配器。

## 5. CFG 与训练适配器只能二选一

MiniMax H3 的常规训练会逐渐解除模型内置的引导蒸馏。当前界面提供两条互斥路线。

### 路线 A：CFG 增强训练，推荐作为默认路线

- “CFG 增强训练”填 `4`；
- “训练 / 去蒸馏适配器”留空；
- “管道并行阶段数”必须为 `1`；
- 训练会增加一次无梯度的无条件前向，因此速度略慢；
- 配合 Unsloth 时，额外前向基本不增加显存占用。

3 步烟测以及两份云平台文档都采用这条路线。

### 路线 B：实验性训练适配器

- 清空“CFG 增强训练”，不要保留 `4`；
- 在“训练 / 去蒸馏适配器”选择对应权重；
- 该权重会在开始训练前合并进基础模型；
- 它和“适配器配置”中本次要训练、最终要导出的角色/风格 LoRA 不是同一个文件；
- 该第三方方案的实际效果尚未在本项目中独立验证。

若两个字段同时填写，WebUI 会在保存或启动前拒绝该配置。不要用“跳过检查”绕过互斥校验。

## 6. 量化选项应该怎么选

这里有两个不同字段，不要混淆：

1. “基础数据类型（dtype）”选择 `bfloat16`，控制训练计算使用的基础精度。
2. “Diffusion 模型数据类型”选择“保留检查点原生量化”，表示不要覆盖 int8 convrot 权重本身的量化格式。

错误地在第二项选择 `bfloat16`、`float8` 等具体类型，会触发解量化或类型转换，显著增加显存和系统内存压力，也偏离这套 24GB 配置。

检查配置文件时，以“没有 `diffusion_model_dtype` 这一行”为正确结果。

## 7. 24GB 显卡的显存策略

### 7.1 首选组合

- `micro_batch_size_per_gpu = 1`；
- `caching_batch_size = 1`；
- `blocks_to_swap = 48`；
- `activation_checkpointing = 'unsloth'`；
- 先用 `384` 分辨率、`34` 帧跑通；
- 使用 int8 convrot 扩散模型和文本编码器；
- 不填写 `diffusion_model_dtype`。

块交换会把更多模型块移到系统内存。数值越大越省显存，但 CPU、内存带宽和数据交换会让训练变慢。确认 48 能稳定训练后，显存更宽裕的机器可以逐步降低该值来换速度。

### 7.2 缓存完成后训练仍然显存不足

缓存阶段需要加载视频 VAE、音频 VAE 和大型文本编码器。训练器会在缓存后尝试释放这些组件，但某些环境可能仍残留部分系统内存或显存占用。

处理顺序：

1. 在“开始训练”页启用“仅缓存并退出”；
2. 等待缓存完整结束；
3. 正常重启 WebUI 实例或应用；
4. 使用同一项目和未改动的数据集重新开始训练；
5. 只有确认素材、分辨率、帧桶和标注都没有变化时，才复用已有缓存。

数据集发生变化后继续信任旧缓存，可能把旧素材或旧分桶结果带入训练。遇到疑问时优先重新生成缓存。

## 8. 从 WebUI 启动 3 步烟测

1. 在“数据集设置”通过浏览器上传 `2/3/4.mp4` 和同名 `.txt`，保留自动填写的服务器目录。
2. 填写 `[384]`、`[[16, 9]]`、`[34]`、重复次数 `1`，禁用验证集并保存。
3. 在“训练配置”选择 MiniMax H3，通过“识别 MiniMax 四文件”或服务器下载自动填写四个模型路径。
4. 选择“训练输出根目录”。没有独立可写盘时可使用 `/workspace/DiffPipeForge`；页面明确识别到可写持久盘时优先使用 `/cloud/DiffPipeForge`。
5. 设置唯一的输出文件夹名称，例如 `minimax_h3_smoke_01`。
6. 填写上表参数，再次确认 `CFG=4`、训练适配器为空、管道并行阶段数为 1。
7. 确认“Diffusion 模型数据类型”为“保留检查点原生量化”，保存训练配置。
8. 打开“开始训练”。
9. “从检查点恢复”保持空白，第一次烟测必须是新训练。
10. 确认 GPU 数量与当前实例一致，单卡填 `1`。
11. 点击“开始训练”，不要启用“跳过检查”。
12. 观察实时训练日志，等待出现 3 次有限 loss 和 `TRAINING COMPLETE!`。

缓存阶段可能明显长于 3 个反向传播步骤。只要日志仍在读取模型、编码素材或写缓存，就不是 loss 卡死。

## 9. 如何判断烟测成功

同时满足下面条件才算通过：

- 日志中出现 3 个训练步；
- 3 个 loss 都是有限数字，没有 `NaN`、`Inf` 或 Python traceback；
- 日志末尾出现 `TRAINING COMPLETE!`；
- 输出目录内存在第 3 步或最终保存的 LoRA 权重；
- 输出目录内存在 TensorBoard 事件文件；
- 训练运行根目录内存在 `latest` 文件和它指向的 `global_step...` 子目录；
- `global_step...` 内存在非空的 `*_model_states.pt`。

3 个 loss 可以上下波动。烟测的结论是“训练链可运行”，不是“模型已经收敛”。若第 1 步比第 3 步低，也不能仅据此判定配置错误。

## 10. 从第 3 步恢复到第 4 步

“从检查点恢复”接收的是训练运行根目录，不是文件。完成 3 步烟测后，使用同一项目做一次 3→4 步恢复验收：

1. 回到“训练配置”，只把“最大训练步数”从 `3` 改成 `4`。
2. 保持数据集、模型、输出根目录、输出文件夹名称和其他训练参数不变，保存训练配置。
3. 返回“开始训练”，点击检查点列表旁的“刷新”。
4. 在“从检查点恢复”下拉建议中选择刚才的运行根目录；该目录必须直接包含 `latest`。
5. 保持 GPU 数量不变并启动训练。
6. 日志应从已保存状态继续，只新增第 4 步，而不是从第 1 步重新开始。
7. 等待第 4 个有限 loss 和 `TRAINING COMPLETE!`。
8. 再次刷新，确认 `latest` 已更新到第 4 步对应的 `global_step...`，且其中的 `*_model_states.pt` 非空。

正确目录结构示例：

```text
minimax_h3_run_timestamp/
├── latest
├── global_step3/
│   └── ..._model_states.pt
├── events.out.tfevents...
└── step3/
    └── adapter_model.safetensors
```

应选择 `minimax_h3_run_timestamp/`，不要选择：

- `latest` 文件；
- `global_step3/` 子目录；
- `.safetensors` 权重文件。

检查点路径是启动参数，不会写回 `trainconfig.toml`。恢复前修改 `max_steps` 不会改变原运行根目录；选择正确目录后，训练状态会继续写入该运行。

## 11. 验证不同训练会话互相隔离

完成 3→4 步恢复后：

1. 在“开始训练”页清空“从检查点恢复”。
2. 新建项目，或至少把输出文件夹名称改成新的唯一名称，例如 `minimax_h3_isolation_02`。
3. 保存训练配置，返回“开始训练”并点击“刷新”。
4. 新 `output_dir` 尚未训练时，下拉列表应为空，旧烟测运行不应出现在列表里。
5. 如需实跑验证，可把最大训练步数设为 `1`；新训练应创建另一个运行根目录，并从第 1 步开始。

下拉探测只扫描当前 `trainconfig.toml` 的 `output_dir` 直属运行目录，因此不同项目和不同输出目录默认隔离。手动输入绝对路径可以明确跨目录恢复；只有确认目标属于所需会话时才应这样做。

## 12. 烟测通过后改为正式训练

不要在烟测目录上直接覆盖正式训练。建议新建项目或至少使用新的输出文件夹名称，然后：

1. 把数据集路径换成完整数据集；
2. 按真实视频长度增加 17 的倍数帧桶，例如 `[34, 68, 102]`；
3. 按数据宽高比补充分桶，不要把所有素材强制写成 16:9；
4. 删除或清空“最大训练步数 = 3”的烟测限制；
5. 按计划设置 epoch、保存间隔和验证集；
6. 根据目标把 LoRA rank 从 8 调整为 16、32 等；
7. 先保留 24GB 显存组合，确认余量后再提高分辨率、帧数或降低块交换数量；
8. 正式长训前确认输出目录位于平台可持久化的位置。

## 13. 常见问题

### 启动前提示缺少模型

四个路径都必填：Diffusion、视频 VAE、音频 VAE、Qwen3-VL 文本编码器。只填三个不能启动，纯图片数据集也不能省略音频 VAE。

### 提示 CFG 与适配器冲突

烟测采用 `CFG=4`，清空“训练 / 去蒸馏适配器”。若确实要试第三方适配器，则反过来清空 CFG。

### 提示管道并行阶段数错误

只要 CFG 大于 1，管道并行阶段数就必须是 1。不要按多卡数量自动改成大于 1。

### loss 是 NaN 或 Inf

停止训练，不要继续烧卡。先核对视频可解码、标注存在、学习率为 `1e-4`、量化覆盖保持空白、基础 dtype 为 bfloat16，再用同一套 3 样本烟测重新验证。

### 第 3 步有权重但没有可恢复检查点

确认训练是正常结束而不是强制杀进程；正常达到 `max_steps=3` 会在退出前保存最终训练状态。只有 LoRA `.safetensors` 不能用于恢复优化器和数据加载器状态。

### 训练很慢但显存没有溢出

`blocks_to_swap=48` 优先保证 24GB 可运行，速度变慢是预期代价。正式训练前可逐步降低到 47、46 等并观察峰值显存，不要在同一次排障里同时提高分辨率和降低块交换。
