# 在优云智算部署并验证 DiffPipeForge

本文面向从优云智算镜像创建 Linux 实例的普通用户。数据上传、模型选择、参数填写、训练、检查点恢复和日志验收全部在浏览器中完成，不需要 SSH 客户端或命令行。

| 镜像信息 | 内容 |
| --- | --- |
| 镜像标题 | **DiffPipeForge 全模型训练 WebUI** |
| 版本 | `v1.4.4-youyun-20260810` |
| 训练界面 | `SD-WebUI:7860` |
| 最低验收显存 | 24GB NVIDIA GPU |

MiniMax H3 各字段的含义和 24GB 显存配置原理见 [MiniMax H3 训练参数与 24GB 显存指南](../models/minimax_h3_training_zh.md)。第一次使用时，先严格跑完本文的 3 步训练、恢复到第 4 步和新会话隔离检查，再开始正式长训。

## 1. 镜像包含什么

该镜像提供 DiffPipeForge Linux 训练 WebUI、训练环境、项目当前支持的模型模块及其运行依赖，并配置了开机自动启动。它不是 ComfyUI 推理镜像。

- 普通用户入口：`SD-WebUI:7860`；
- JupyterLab `8888`：仅供管理员或熟悉 Linux 的用户做高级排障和文件管理；
- 登录 WebUI 不依赖 JupyterLab；
- 普通训练流程不要求用户打开终端、执行脚本或手动启动服务；
- 经典 Cosmos 1 训练不在本版本的云端验收范围内。

## 2. 存储位置与关机语义

| 项目 | 优云实例中的位置或行为 |
| --- | --- |
| 项目源码 | `/workspace/DiffPipeForge` |
| 训练 Python | `/usr/local/miniconda3/envs/py312/bin/python` |
| 浏览器上传目录 | 页面自动创建；当前实例通常为 `/workspace/DiffPipeForge/web_uploads/dataset-...` |
| 推荐输出根目录 | 当前没有独立可写盘时为 `/workspace/DiffPipeForge` |
| 公共模型挂载 | `/model`，只读 |
| 普通关机后再开机 | 原实例的 `/workspace` 仍保留 |
| 删除实例 | 只存在于 `/workspace` 的上传、训练结果和检查点会随实例丢失 |
| 从原镜像新建另一实例 | 不会带上旧实例运行后新增的数据 |

`/model` 只能读，不能保存数据集、缓存、LoRA、日志或检查点。若平台实际挂载了可写的独立 `/cloud`，WebUI 会把它识别为持久存储，并优先推荐 `/cloud/DiffPipeForge` 作为输出根目录、`/cloud/DiffPipeForge/uploads` 作为上传目录、`/cloud/DiffPipeForge/models` 作为模型下载目录。没有真实挂载时，界面不会创建一个假的“持久盘”。

普通关机不会清空同一实例的 `/workspace`，但它不是跨实例持久盘。删除实例前必须下载结果、复制到可写持久盘，或按平台流程把当前实例另存为镜像并等待制作完成。

## 3. 从镜像创建实例

1. 打开优云智算的镜像市场或私有镜像页面。
2. 选择 **DiffPipeForge 全模型训练 WebUI**，版本确认是 `v1.4.4-youyun-20260810`。
3. 选择至少 24GB 显存的 NVIDIA GPU。本文的 MiniMax H3 int8 LoRA 验收以 24GB 为最低档位。
4. 为系统盘和可写盘预留数据集、缓存、日志、检查点和模型空间。
5. 若账号的云硬盘已经保存 MiniMax H3，在模型挂载步骤中把它挂载到 `/model`。
6. 应用入口保留 `JupyterLab:8888`，并确认同时存在 `SD-WebUI:7860`。训练入口必须是 7860，不能用 ComfyUI 8188 代替。
7. 创建并启动实例，等待平台状态变为“运行中”。

若准备使用 WebUI 从服务器下载 MiniMax H3，下载目标至少需要 **60 GiB 可用空间**。四个权重文件本身共 `53,924,785,072` 字节，下载缓存、临时文件和文件系统余量还会额外占用空间。

## 4. 登录 WebUI

镜像已配置自动启动。实例进入运行状态后：

1. 在**当前实例卡片**中找到“SSH 端口”和“实例密码”。
2. 点击 `SD-WebUI:7860` 打开训练界面。
3. 在登录页分别粘贴当前实例的 SSH 端口和实例密码，然后登录。
4. 登录成功后应进入 DiffPipeForge 主界面，并能看到“数据集设置”“训练配置”“开始训练”“全局监控”和“系统诊断”。

这里使用 SSH 端口和实例密码只是为了验证当前实例身份。用户不需要开启终端，不需要连接 SSH，也不需要执行任何命令。不要填写 JupyterLab token、其他实例的端口或账号登录密码。

连续输错会触发短时限速。字段看似正确却无法登录时，重新从当前实例卡片复制，不要沿用旧实例的凭据。登录会话使用安全 Cookie；端口和密码不会写入训练 TOML、项目文件或任务日志。

## 5. 新建独立项目并选择输出位置

1. 在主菜单选择“新建项目”。
2. 进入“训练配置”，在“训练输出根目录”区域点击“使用平台推荐目录”。
3. 当前没有独立可写盘时，推荐值应为 `/workspace/DiffPipeForge`；若界面明确把 `/cloud` 标为可写持久盘，可改选 `/cloud/DiffPipeForge`。
4. 把“输出文件夹名称”设为本会话独有的名称，例如 `minimax_h3_smoke_01`。
5. 不要让两个项目或两次独立训练共用同一个输出文件夹名称。

WebUI 会把根目录和输出名称组合成标准 `output_dir`。界面专用的 `output_base_dir` 不会写入 `trainconfig.toml`。训练开始后，训练器还会在 `output_dir` 下创建本次运行目录：

```text
/workspace/DiffPipeForge/minimax_h3_smoke_01/
└── <本次运行目录>/
    ├── latest
    ├── global_step.../
    ├── events.out.tfevents...
    └── ...
```

检查点下拉框只扫描当前 `trainconfig.toml` 的 `output_dir` 直属运行目录。不同项目只要使用不同 `output_dir`，检查点就不会混入同一个下拉列表。

## 6. 通过浏览器上传 3 对烟测数据

准备以下 6 个文件；视频和标注的主文件名必须完全一致，标注扩展名必须是精确小写 `.txt`：

```text
2.mp4
2.txt
3.mp4
3.txt
4.mp4
4.txt
```

上传步骤：

1. 打开“数据集设置”。
2. 点击“选择视频和标注”，一次选择上述 6 个文件。
3. 页面应显示 3 个视频、3 个标注且没有配对错误。
4. 点击“上传并使用此数据集”。
5. 等待进度到 100%，确认“输入路径”已经由 WebUI 自动填写。

当前没有 `/cloud` 持久盘时，自动路径形如：

```text
/workspace/DiffPipeForge/web_uploads/dataset-20260810-123456-xxxxxxxxxx
```

若存在真实可写 `/cloud`，自动路径形如 `/cloud/DiffPipeForge/uploads/dataset-...`。实际路径以页面显示为准；浏览器上传用户**不要**再手动把它改成 `/workspace/data`，也不要填写本机 `C:\...` 路径或单个视频文件。

上传只有在所有文件均通过扩展名、大小和同名配对检查后才会完成并自动填入路径。失败或取消的未完成会话会被回收。已有服务器数据也可以使用路径旁的文件夹按钮浏览，不需要借助 JupyterLab 或 SSH。

### 烟测数据集参数

| 字段 | 值 |
| --- | --- |
| 分辨率 | `[384]` |
| 启用宽高比分桶 | 启用 |
| 自定义宽高比分桶 | `[[16, 9]]` |
| 帧数分桶（视频） | `[34]` |
| 重复次数 | `1` |
| 验证集 | 禁用 |

最小宽高比 `0.5`、最大宽高比 `2.0` 和分桶数量 `7` 可保留默认值。保存“训练数据集配置”后再进入训练配置。

## 7. 准备 MiniMax H3 四个模型文件

MiniMax H3 必须同时提供扩散模型、视频 VAE、音频 VAE 和 Qwen3-VL 文本编码器。即使只训练图片，也不能省略音频 VAE。可在 WebUI 中选择下面任一方式。

### 方式 A：识别已经挂载到 `/model` 的模型

若云硬盘已经挂载，常见根目录是：

```text
/model/ModelScope/Comfy-Org/MiniMax-H3
```

1. 在“训练配置”把“模型架构”设为 `MiniMax H3`。
2. 在模型管理器点击“识别 MiniMax 四文件”。
3. 等待 WebUI 按文件大小和 SHA-256 校验完整四件套。
4. 识别成功后，四个模型字段会自动填写；逐项核对下表路径。

| WebUI 字段 | `/model` 中的精确路径 | 字节数 |
| --- | --- | ---: |
| Diffusion 模型路径 | `/model/ModelScope/Comfy-Org/MiniMax-H3/diffusion_models/minimax_h3_fl2va_pruned_int8_convrot.safetensors` | `20,970,379,616` |
| 文本编码器路径（Qwen3-VL） | `/model/ModelScope/Comfy-Org/MiniMax-H3/text_encoders/qwen3vl_32b_minimax_h3_int8_convrot.safetensors` | `27,141,342,152` |
| VAE 路径 | `/model/ModelScope/Comfy-Org/MiniMax-H3/vae/minimax_h3_video_vae_fp16.safetensors` | `5,207,808,496` |
| 音频 VAE 路径 | `/model/ModelScope/Comfy-Org/MiniMax-H3/vae/minimax_h3_audio_vae_fp32.safetensors` | `605,254,808` |

`/model` 是只读的；识别只读取和校验，不会复制或修改模型。

### 方式 B：由 WebUI 在服务器端下载

不要先下载到本机再上传。让云服务器直接下载：

1. 在“训练配置”选择 `MiniMax H3`。
2. 点击“一键准备 MiniMax H3”。
3. 中文界面默认可选择 `ModelScope`，仓库为 `Comfy-Org/MiniMax-H3`，revision 为 `master`；也可以选择 Hugging Face 的界面预置固定 revision。
4. 确认清单只包含上表四个精确相对路径。
5. 下载目标选择可写目录：有独立持久盘时使用 `/cloud/DiffPipeForge/models/MiniMax-H3`；否则使用 `/workspace/DiffPipeForge/models/MiniMax-H3`。
6. 确认目标盘至少有 60 GiB 可用空间，再点击“开始服务器下载”。
7. 页面显示完成后，四个模型字段会自动填入下载后的服务器绝对路径。

服务器下载支持正式缓存和未完成文件续传；重试时使用同一目标目录，不要另建多个副本。令牌只从服务器环境变量读取，不会写入训练 TOML 或下载任务日志。

四个文件总计：

```text
53,924,785,072 bytes
```

若下载到 `/workspace`，普通关机后同一实例仍可继续使用，但删除实例后不会保留；若要跨实例复用，应使用真实可写 `/cloud` 或另做镜像。

## 8. 填写 24GB MiniMax H3 烟测参数

### 模型加载

- 基础数据类型：`bfloat16`；
- Diffusion 模型数据类型：`保留检查点原生量化`；
- 时间步采样方法：`uniform`；
- Shift：`8`；
- Image Shift：`1`；
- CFG 增强训练：`4`；
- 训练 / 去蒸馏适配器：留空。

选择“保留检查点原生量化”后，`trainconfig.toml` 不写 `diffusion_model_dtype`，这是正确结果。

### 训练和显存

- 批次大小（每 GPU）：`1`；
- 梯度累积步数：`1`；
- 管道并行阶段数：`1`；
- 激活检查点：`Unsloth（极致节省显存）`；
- 交换块数量：`48`；
- 缓存批次大小：`1`；
- 编译模型：首次烟测关闭。

### LoRA 与优化器

- 适配器类型：`LoRA`；
- Rank：`8`；
- 适配器数据类型：`bfloat16`；
- 优化器：`AdamW Optimi`；
- 学习率：`1e-4`。

### 终止和保存

- 最大训练步数：`3`；
- 每 N 步保存模型：`3`；
- 日志打印间隔步数：`1`；
- 验证集：禁用。

保存训练配置。再次确认当前项目、输出根目录和输出名称都属于本次烟测。

## 9. 第一次启动：完成 3 步训练

1. 打开“开始训练”。
2. 确认配置概览中的模型类型、数据集和 `output_dir`。
3. “从检查点恢复（选择或输入运行目录）”保持空白。
4. 单卡实例的 GPU 数量填 `1`。
5. 不勾选“跳过检查”。
6. 点击“开始训练”。
7. 等待模型读取和数据缓存完成。大型文本编码器会让缓存阶段明显长于 3 个训练步。
8. 在实时日志中等待 3 个有限 loss 和 `TRAINING COMPLETE!`。

3 个 loss 可以上下波动，但不能是 `NaN`、`Inf`，也不能出现 Python traceback。页面能打开不等于训练可用；只有这 3 步完成，才同时验证模型加载、数据缓存、反向传播、保存和检查点链路。

本次运行根目录应至少包含：

- 最终或第 3 步保存的 `adapter_model.safetensors`；
- `events.out.tfevents...`；
- `latest` 文件；
- `latest` 指向的 `global_step3/`；
- `global_step3/` 内非空的 `*_model_states.pt`。

## 10. 纯 WebUI 恢复验收：从第 3 步续跑到第 4 步

不要新建项目，也不要改输出文件夹名称。按下面顺序操作：

1. 回到“训练配置”，把“最大训练步数”从 `3` 改成 `4`。
2. 保持模型、数据集、输出根目录、输出名称和其他参数不变，保存训练配置。
3. 回到“开始训练”，点击检查点列表旁的“刷新”。
4. 在“从检查点恢复”下拉建议中选择刚才那次运行的**根目录**。正确项内部含有 `latest`，并显示其指向的 `global_step3`。
5. 不要选择 `latest` 文件、`global_step3/` 子目录或 `adapter_model.safetensors`。
6. 保持 GPU 数量为 `1`，点击“开始训练”。
7. 日志应从已保存的第 3 步状态恢复，只新增第 4 步，而不是重新从第 1 步开始。
8. 等待第 4 个有限 loss 和 `TRAINING COMPLETE!`。
9. 再次刷新检查点，确认 `latest` 已更新到第 4 步对应的 `global_step...`，并且状态文件非空。

恢复路径只作为本次启动参数发送，不会写入 `trainconfig.toml`。它必须是文件夹，而且必须是含 `latest` 的运行根目录。

## 11. 新会话隔离验收

完成 3→4 步恢复后，再验证另一次训练不会误接旧检查点：

1. 在“开始训练”页清空“从检查点恢复”。
2. 新建项目，或至少把输出文件夹名称改成全新的唯一名称，例如 `minimax_h3_isolation_02`。
3. 保存训练配置后回到“开始训练”，点击“刷新”。
4. 新 `output_dir` 尚未训练时，下拉列表应为空；旧会话的运行目录不应出现在这里。
5. 若要做快速隔离烟测，可把最大训练步数设为 `1`，启动并确认它创建新的运行根目录，日志从第 1 步开始。
6. 后续正式训练同样先清空恢复路径，并为每个独立任务使用新的项目或输出名称。

自动探测的隔离边界是当前配置的 `output_dir`。手动输入绝对路径可以明确跨目录恢复，因此只有在用户确实要恢复该会话时才应手动填写。

## 12. 正式训练前的调整

烟测通过后，不要直接覆盖烟测目录。新建项目或使用新的输出名称，然后：

1. 上传或选择完整数据集；
2. 按视频长度使用 17 的倍数帧桶，例如 `[34, 68, 102]`；
3. 按真实素材比例设置宽高比桶；
4. 清空烟测的“最大训练步数 = 3/4”限制，改为正式计划；
5. 重新设置 epoch、保存间隔、验证集和 LoRA rank；
6. 先保留 `blocks_to_swap=48` 与 Unsloth，确认显存余量后再优化速度；
7. 确认正式输出所在存储在删除实例后是否仍可保留。

## 13. 停止训练和关闭实例

### 正常结束

1. 等日志出现 `TRAINING COMPLETE!`。
2. 确认 LoRA、事件文件、`latest` 和 `global_step...` 均已写完。
3. 下载重要结果，或复制到可写持久盘。
4. 回到优云控制台关机。

### 中途停止

先在 WebUI 点击“停止训练”，等待训练进程退出，再关机。不要在正在写检查点时直接强制断电，也不要把“关机”和“删除实例”混为一谈。

### 删除实例前

至少完成一种保存方式：

- 下载 LoRA、TensorBoard 事件和完整检查点运行目录；
- 复制到真实可写的持久盘；
- 把当前实例另存为私有镜像，并等待镜像制作完成。

只读 `/model` 不能作为备份目的地。

## 14. 管理员鉴权与代理验收矩阵

普通用户无需执行本节。镜像发布或启动脚本变更后，管理员应在平台 HTTPS 应用入口逐项复验：

| 验收项 | 期望结果 |
| --- | --- |
| 匿名打开 `/` | `200`，只显示登录页，不返回训练 SPA |
| 匿名访问 `/healthz` | `200`，供平台健康检查使用 |
| 匿名访问受保护 `/api/*` | `401` |
| 错误 SSH 端口或实例密码 | `401`，不下发会话 Cookie |
| 当前实例正确端口和密码 | `200`，进入训练界面 |
| 登录 Cookie | 同时具备 `HttpOnly`、`Secure`、`SameSite=Strict` |
| 已登录访问受保护 API | `200` |
| 异源写请求 | `403` |
| 匿名 WebSocket 握手 | 拒绝，不能收到实时训练日志 |
| 已登录、同源 WebSocket | 握手成功，可接收实时日志 |
| 异源 WebSocket | 拒绝 |
| 点击退出后再次访问 API | `401` |
| 退出时仍连接的 WebSocket | 服务端主动关闭，关闭码 `4401` |

部署约束：

- 启动脚本必须设置 `DIFFPIPE_WEB_AUTH=youyun`；
- 服务只接受符合平台实例格式的主机名，环境不符时应拒绝启动，不能静默降级到无鉴权；
- 对外必须使用平台 HTTPS 应用代理，不能把 7860 原始 HTTP 直接暴露到公网；
